# TerraLens

**Спутниковая история поля: от контура на карте до восстановленного NDVI и проверяемого результата.**

[![Backend and ML](https://github.com/ArtycoBW/Terralens/actions/workflows/backend-ml.yml/badge.svg)](https://github.com/ArtycoBW/Terralens/actions/workflows/backend-ml.yml)
[![Frontend](https://github.com/ArtycoBW/Terralens/actions/workflows/frontend.yml/badge.svg)](https://github.com/ArtycoBW/Terralens/actions/workflows/frontend.yml)

TerraLens помогает изучить состояние сельскохозяйственной территории за выбранный период. Пользователь сохраняет контур, сервис собирает Sentinel-2, Landsat и погоду, восстанавливает пропуски NDVI и показывает отклонения от истории поля. Наблюдения, оценки модели и отсутствие данных различаются в интерфейсе и экспорте.

Решение подготовлено для кейса о мониторинге вегетационной динамики сельскохозяйственных территорий: восстановление пропусков NDVI и интерпретация негативных аномалий. В репозитории два проверяемых результата: **веб-приложение с реальным сбором данных** и **автономный ML-пакет с готовыми submission для двух предоставленных тестовых входов**. Для запуска готовой версии обучение не требуется.

**Материалы для защиты:** [презентация, 15 слайдов](deliverables/presentation/TerraLens-defense.pptx), [сценарий выступления, демо и ответы](docs/DEFENSE_GUIDE.md), [три реальных поля с графиками и CSV](docs/analysis/field-cases/REPORT.md). Слайды содержат редактируемые таблицы, диаграммы и заметки докладчика. Пример из Воронежской области показывает негативное отклонение от истории, без заявления подтверждённого агрономического диагноза.

Историческая проверка модели **`131aee618934151e`** выполнена на 40 наблюдаемых датах трёх полей. На одиночных масках она уступила M0: RMSE **0,05322 против 0,03754**; на парах соседних дат средний результат лучше: **0,06677 против 0,07637**. Все ухудшения и ограничения опубликованы. ## Быстрый запуск

Нужны Git и Docker с Compose v2 и запущенным daemon. На Windows удобно использовать Docker Desktop в режиме Linux containers. Во время первой сборки и для нового спутникового анализа нужен интернет.

```sh
git clone https://github.com/ArtycoBW/Terralens.git
cd Terralens
docker compose up --build -d
docker compose ps
```

| Адрес | Что проверить |
|---|---|
| [localhost:3001](http://localhost:3001) | Лендинг и вход в приложение |
| [localhost:3001/app](http://localhost:3001/app) | Рабочая карта; гостевая сессия создаётся автоматически |
| [localhost:8000/api/v1/docs](http://localhost:8000/api/v1/docs) | Swagger с фактической схемой API |
| [localhost:8000/api/v1/health/ready](http://localhost:8000/api/v1/health/ready) | Готовность API, БД, Redis и зарегистрированной модели |

Compose запускает миграции и регистрирует включённую модель, затем поднимает API, worker, scheduler и frontend. Состояние `migrate: Exited (0)` ожидаемо. База и результаты сохраняются в Docker volumes между перезапусками.

Для локальной проверки `.env` не обязателен: действуют значения Compose. Параметры перечислены в [.env.example](.env.example). Порт frontend меняется через `FRONTEND_PORT`; по умолчанию заняты `3001`, `8000`, `54329`, `56379`, доступ только с этого компьютера. Для публичного размещения задайте свой секрет, разрешённые домены, HTTPS и secure cookies.

```sh
docker compose logs --tail=80 backend worker
# Остановить, сохранив данные
docker compose stop
# Возобновить работу
docker compose up -d
```

## Что попробовать за пять минут

1. Откройте карту. Найдите **Potsdam**, приблизьте территорию и выберите контур OSM либо нарисуйте собственный: минимум три вершины, затем клик по первой точке или Enter. Можно импортировать [готовый GeoJSON](backend/tests/fixtures/potsdam.geojson).
2. Сохраните поле. В его паспорте выберите **01–10 июня 2024** и запустите анализ. Сбор обращается к внешним сервисам и может занимать несколько минут; прошлые сезоны входят в общий прогресс.
3. Посмотрите NDVI, погоду, происхождение значений и раздел качества. `Частичные данные` — полноценный результат с перечисленными ограничениями, а не скрытая ошибка.
4. Запустите другой период или другое поле. В разделе сравнения выберите до четырёх завершённых анализов, переключите календарные даты и совмещение сезонов.
5. Скачайте CSV, GeoJSON или JSON и manifest. В разделе **Бенчмарк** проверьте готовые прогнозы на предоставленном наборе, а в **Модели** — версию и метрики.

## Архитектура

![Контейнерная архитектура TerraLens](docs/architecture/containers.svg)

Frontend обращается к API через Next.js под одним origin. Django хранит геометрию, версии и задания в PostGIS; Celery исполняет сбор и расчёт в фоне через Redis. Worker импортирует `terralens_ml` и сохраняет результат атомарно. Снимки источников, копии моделей и экспорты лежат в общем файловом volume. Scheduler восстанавливает доставку заданий и обслуживает срок хранения.

ML — самостоятельный Python-пакет, используемый также через CLI. Отдельного ML HTTP-сервиса в приложении нет. [Границы компонентов, последовательность анализа, сущности и поток обучения](docs/ARCHITECTURE.md).

| API и геоданные | Python 3.12, Django 5.2 LTS, GeoDjango, Django REST Framework, PostgreSQL 16 / PostGIS 3.5 |
| Задания | Celery, Redis 7.4, Celery Beat |
| Вычисления | pandas, NumPy, SciPy, scikit-learn, CatBoost, rasterio, Shapely |
| Воспроизводимость | Docker Compose, uv.lock, requirements.lock, pnpm-lock.yaml, GitHub Actions |

## Как обучалась текущая модель

### Данные и разбиение

Обучение использовало предоставленный `train_dataset.csv`: после нормализации он совпадает с содержимым `train-dataset.zip`. Полный набор содержит 99 955 строк, 39 AOI и 30 520 известных целей за 2010–2024 годы. Новый CSV не увеличил объём train. Внешние обучающие наборы и предобученные модели не использовались.

Из полного набора для final fit взяты **21 selection AOI за 2010–2023 годы**. В этом срезе **14 977 пригодных целевых значений**. 2024 год исключён из обучения и текущего development. Остальные поля разделены заранее:

| Назначение | Полей | Использование в последней волне |
|---|---:|---|
| Selection | 21 | Выбор параметров по пяти GroupKFold; затем обучение финального ансамбля |
| Calibration | 5 | Только калибровка интервалов после выбора модели |
| Assessment | 5 | Исключены из fit и выбора; повторная оценка не выполнялась |
| Ранее просмотренный holdout | 8 | Полностью исключён из текущей волны |

Все годы одного AOI остаются в одном пространственном fold. На каждом шаге модель и глобальные priors обучаются только на тренировочных AOI этого fold; открытые наблюдения проверяемого поля служат ретроспективным контекстом. Случайного разделения строк одного поля между train и validation нет. Точные ID, состав folds и контрольные суммы сохранены в [плане эксперимента](docs/analysis/rmse-wave/plan.json) и [training_scope артефакта](ml/artifacts/final/manifest.json).

### Подготовка контекста и обучающие маски

Строки проверяются на корректность дат и уникальность `(anon_polygon_id, date)`. Календарь вычисляется из даты. Raw NDVI сохраняется; для обучения и опорных наблюдений используются конечные значения в **[−1; 1]**. При оценке истинные цели не обрезаются и не исправляются. Расчёты соседей изолированы по полю, сезону и непрерывному отрезку одной культуры; переход wheat → maize → wheat образует три отрезка. Техническое начало сезона — январь.

Модель учится восстанавливать искусственно скрытые известные значения:

1. Для каждого seed пригодные цели поля/сезона перемешиваются и делятся на **пять непересекающихся частей**. Каждая цель скрывается ровно один раз в point-масках; доля одной части — около 20%.
2. После каждой point-маски строится block-маска. Начало выбирается среди наблюдений, ширина — из **8, 15, 30, 45, 65 календарных дней**. Получаются пять point- и пять block-масок на члена ансамбля.
3. В скрытых строках до расчёта признаков удаляются target, спутниковые индексы, погода, готовая климатология и zscore/status. Сохраняются дата и культура. Признаки и обучаемые priors пересчитываются заново из разрешённого контекста.
4. В обучающую матрицу попадают признаки скрытых строк и их residual targets. Суммарно для трёх членов ансамбля получено **79 256 примеров**, покрывающих все **14 977** пригодных целей. Это число включает повторения целей между масками и членами ансамбля, а не столько независимых наблюдений.

В validation применяются отдельные фиксированные seeds **42 и 137**, доля маски **0,15**, сценарии points и blocks. Для всех кандидатов проверено точное совпадение **8 912** ключей, истинных значений и длин пропусков. Тесты проверяют, что изменение скрытых значений не меняет признаки или прогноз.

### Что предсказывает CatBoost

База **M0** усредняет ближайшее пригодное наблюдение слева и справа. При единственном близком соседе используется крайний fallback. Максимальная длина внутреннего пропуска — **60 дней**, допустимое расстояние на краю — **14 дней**; при недостатке контекста используются обученные crop/month prior, month prior и train median.

Каждый CatBoost обучается на остатке `y_true − M0`. Итог для пропуска:

```text
NDVI = M0 + (residual_seed42 + residual_seed107 + residual_seed211) / 3
```

Функция потерь — **RMSE**. Члены ансамбля обучаются последовательно с двумя CPU-потоками. Каждый получает свои маски по seed; веса членов равны. Используются фиксированные 600 итераций без подбора числа деревьев на test. `clip: false`: готовые оценки не обрезаются к [−1; 1]. Чистые наблюдаемые значения сохраняются без коррекции.

**78 признаков** включают:

- Базовую оценку, число опорных наблюдений, длину gap, признак prior fallback и sin/cos дня года.
- Два наблюдения primary с каждой стороны, календарные расстояния, наклоны, линейную оценку и count/mean/std в окнах ±14/30/60 дней.
- Интерполированные NDVI/EVI/NDWI доступных сенсоров, давность и интервал опорных дат; ближайшая сенсорная опора должна быть не дальше 14 дней. MODIS участвует только при наличии соответствующих столбцов во входе.
- Предыдущее/следующее NDVI каждого сенсора и наклон, медиану `primary − sensor` на не менее трёх совместных видимых датах в окне ±60 дней, число пар и скорректированную оценку.
- Число доступных NDVI-сенсоров и разброс их оценок.

Пропуски в признаках остаются NaN для обработки CatBoost. AOI ID, погода, готовые zscore/климатология и культура как отдельный категориальный признак в ансамбль не входят; культура задаёт границы контекста и prior. Дополнительные `transition_features` и `sensor_alignment` исследованы, но в текущей модели отключены. Полный порядок столбцов — в `feature_schema` [manifest](ml/artifacts/final/manifest.json).

### Выбор параметров и отклонённые варианты

До обучения зафиксированы пять кандидатов и условия допуска: **не менее 1%** снижения pooled point RMSE, block RMSE не хуже baseline, улучшение points минимум в **4 из 5 folds**, положительная нижняя граница 95% парного AOI-bootstrap выигрыша. Из допущенных выбирается минимальный point RMSE. Pooled RMSE считается по всем контрольным прогнозам, а не усреднением пяти RMSE.

| Вариант | Point RMSE ↓ | Block RMSE ↓ | Решение |
|---|---:|---:|---|
| Baseline: 3 × 400 деревьев, depth 5, LR 0,04, L2 10 | 0,068260 | 0,094173 | Версия сравнения |
| Равный суммарный вес каждой исходной цели | 0,067794 | 0,095044 | Отклонён: ухудшение blocks и выигрыш points <1% |
| Семь point-масок при прежних пяти block-масках | 0,068360 | 0,094087 | Отклонён: points хуже |
| Шесть признаков независимых пар S2↔Landsat | 0,068331 | 0,094134 | Отклонён: points хуже |
| 3 × 800 деревьев, depth 5, LR 0,025, L2 10 | 0,067495 | **0,093104** | Прошёл условия, но уступил по основной метрике |
| **3 × 600 деревьев, depth 6, LR 0,03, L2 20** | **0,067357** | 0,093206 | **Выбран** |

Вариант с 800 деревьями немного лучше на blocks, выбранный — на основной метрике points. Комбинацию отклонённых изменений не обучали. В предыдущем этапе расширение train и признаки PCHIP/переходов также не дали достаточного устойчивого выигрыша: [история экспериментов](docs/analysis/transition-training/REPORT.md).

У выбранной модели points улучшились во всех пяти folds. Парный bootstrap пересэмплирует **целые 21 AOI**, 3 000 повторов, seed 42. 95% интервал абсолютного снижения RMSE: **[0,000529; 0,001282]** для points и **[0,000561; 0,001369]** для blocks. Это оценка на уже использованном development после выбора кандидатов; она не устраняет эффект множественных сравнений и не заменяет новый независимый holdout.

### Финальное обучение и интервалы

После выбора параметров ансамбль заново обучен на всех 21 selection AOI до 2024 года. Затем на пяти отдельных calibration AOI того же временного среза построены point/block-маски с seed **991**, долей **0,15**: **1 173** контрольных примера. По абсолютным ошибкам итогового ансамбля рассчитаны эмпирические радиусы номинального уровня **90%**:

| Группа | N | Радиус NDVI | Правило |
|---|---:|---:|---|
| short | 577 | 0,098537 | Квантиль группы |
| long | 244 | 0,137231 | Квантиль группы |
| edge | 71 | 0,130367 | Общий квантиль, поскольку N < 100 |
| prior | 281 | 0,177646 | Квантиль группы |

Длинный, крайний и prior-контекст не получают интервал уже short. Интервалы новых весов не проверялись на внешней выборке. Номинальные 90% не означают доказанное покрытие новых полей; live-runtime явно отмечает domain shift. [Final fit и калибровка](docs/analysis/rmse-wave/final-fit.json).

### Скорость, артефакт и воспроизведение обучения

Обучение выполнено на **CPU, macOS arm64, Python 3.12.9, CatBoost 1.2.10** с зависимостями из `uv.lock`. Матрицы признаков кешировались в числовом NPZ без pickle; повторное использование разрешено только при совпадении контекста, маски, параметров признаков и контрольных сумм. Кеш ускоряет исследования и не нужен для инференса.

Ранее pandas-циклы при подготовке признаков и интервалов заменены операциями NumPy: время восстановления старых весов сократилось примерно на 70% при точном совпадении результатов. Для новых весов выполнены **10 чередующихся прогретых вызовов полного `reconstruct`** на каждую модель и вход, два CatBoost-потока:

| Вход | Прежние веса с ускоренным runtime | Новые веса | Замедление |
|---|---:|---:|---:|
| `test-dataset.csv`, 57 185 строк | 1,248 с | 1,297 с | 3,98% |
| `test_features.csv`, 49 190 строк | 1,042 с | 1,115 с | 7,01% |

Указаны медианы вычисления после загрузки CSV и модели. Импорт, чтение/запись, HTTP, БД и спутниковый сбор не входят в замер. Это не p95 полного веб-сценария. [Все повторы и условия](docs/analysis/rmse-wave/inference-timing.json).

Рабочий артефакт находится в [ml/artifacts/final](ml/artifacts/final/manifest.json): JSON schema v3, три модели, priors, конфигурация, 78 столбцов, training scope, метрики и калибровка. Manifest хранит SHA-256 данных, кода, lockfile и весов. Его SHA-256 — `798e69c845a7b887802f72f8acde1013d7c31e45b8b58eab1a77a89cc6cf7518`. Он описывает исходный запуск обучения; обновление Git-ветки не меняет этот provenance.

Полный эксперимент воспроизводит [scripts/train_rmse_wave.py](scripts/train_rmse_wave.py) с [конфигурацией](ml/configs/rmse-wave.yaml). До запуска нужны `train_dataset.csv`, прежний baseline `131aee618934151e` и его development OOF по путям `baseline_model` / `baseline_predictions` из config. Большие OOF находятся в игнорируемом `artifacts/` и не входят в чистый клон; прежний development можно пересчитать командой `research --config ml/configs/crop-dynamics.yaml --development-only`, а baseline взять из соответствующей исторической версии Git. Восстанавливаемый кеш обучающих матриц удалён после проверки; промежуточные прогнозы и маски сохранены. Для замера скорости дополнительно нужны оба тестовых входа, без ответов.

Для **нового** запуска скопируйте `ml/configs/rmse-wave.yaml` в `artifacts/rmse-rerun.yaml`, задайте новые `output` и `evidence`, создайте каталог evidence и скопируйте туда [PROTOCOL.md](docs/analysis/rmse-wave/PROTOCOL.md). Затем из корня:

```sh
uv sync --frozen
uv run --frozen python scripts/train_rmse_wave.py --config artifacts/rmse-rerun.yaml --stage develop
uv run --frozen python scripts/train_rmse_wave.py --config artifacts/rmse-rerun.yaml --stage final
uv run --frozen python scripts/train_rmse_wave.py --config artifacts/rmse-rerun.yaml --stage benchmark
```

`develop` фиксирует план, воспроизводит baseline fold 0 и сравнивает кандидатов; `final` обучает выбранный ансамбль и калибрует интервалы; `benchmark` измеряет скорость. Новый артефакт создаётся в `<output>/model`, рабочие веса автоматически не заменяются. Изменение кода, входов или config при продолжении существующего плана отклоняется; повторный final fit и benchmark в прежнем каталоге также запрещены. После обновления ветки используйте новые каталоги, сохраняя исторический план. Повторное обучение может изменить metadata и model_id; проверка готовых весов выполняется отдельными командами ниже.

Перед установкой модель прошла **164 Python-теста**, Ruff, автономные повторы без сети в отдельном ML-окружении и Linux Docker. Для каждого входа четыре результата совпали по SHA-256. Это проверки выпуска до последующей синхронизации ветки; актуальные результаты объединённой версии — в [журнале проверок](docs/VERIFICATION.md). Все решения, конфигурации и ограничения — в [полном отчёте](docs/analysis/rmse-wave/REPORT.md).

## Ограничения и происхождение данных

- Анализ ретроспективный: восстановление может использовать наблюдения по обе стороны пропуска. Это не прогноз будущего урожая.
- Низкое покрытие, облачность, неизвестная история культур, отсутствие трёх сопоставимых сезонов или отказ источника явно отражаются в результате. Аномалия — повод для проверки, а не доказанная причина ущерба.
- Погода взята из Open-Meteo ERA5-Seamless в центре поля: температура ERA5-Land, осадки ERA5. Это сеточные данные, а не датчик на участке. Источники NDVI — Earth Search Sentinel-2 C1 L2A и Planetary Computer Landsat 8/9 C2 L2.
- OSM не содержит всех полей. Гостевое пространство хранится семь дней, экспорт — один день. Лимиты по умолчанию: 20 полей, 10 000 га на контур, 5 000 вершин, период до 366 дней, три активные задачи; актуальные значения отдаёт `/capabilities`.
- Доступность и скорость нового сбора зависят от внешних провайдеров. [Три реальных поля, включая Россию](docs/analysis/field-cases/REPORT.md), проверены с одинаковыми масками; это не глобальная оценка точности. Ограничения числа сцен и отказы источников сохранены.
- Негативный период в Воронежской области подтверждён наблюдаемым отклонением от истории, но его агрономическая причина не размечена. Подготовлены презентация и сценарий защиты; [аудит](docs/CASE_AUDIT.md#6-комплект-защиты-и-внешние-условия) отделяет реализацию от экспертной оценки и организационных вопросов.
- Иллюстрации лендинга сгенерированы, рельеф демонстрационный. Они не выдаются за измерения выбранного поля. Атрибуция карты и лицензии компонентов сохранены в [реестре источников](docs/ATTRIBUTION.md).
