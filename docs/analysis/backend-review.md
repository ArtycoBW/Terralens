# Проверка API, очереди и хранения, 05.09.2026


## Исправленные дефекты

- Старый `latest_run_id` мог указывать на расчёт предыдущей геометрии. Теперь он выбирается только для текущей версии; история прежних анализов сохраняется.
- Повтор от старой отменённой задачи позволял обходить лимит попыток. Повтор разрешён только для последней попытки ресурса, максимум три; состояния discovery/export и `completed_at` анализа сбрасываются согласованно.
- Удаление поля отменяет и расчёты, и экспорт. Истёкшие пространства не запускают новые worker jobs.
- Долгий запрос провайдера мог ошибочно считаться потерянным worker. Отдельный heartbeat продолжает обновляться во время обработки; публикация всё равно проверяет статус и отмену транзакционно.
- Некорректные типы координат могли приводить к 500, а незамкнутые кольца автоматически исправлялись Shapely. Входной GeoJSON теперь явно проверяет типы, замыкание и различные вершины.
- Глобальный bbox мог обходить квоту: геодезическая площадь кольца шириной 360° получалась нулевой. Для viewport применяется площадь между параллелями; глобальный запрос отклоняется.
- Одинаковый `model_id` мог перезаписать сведения зарегистрированной версии. Другой manifest с тем же идентификатором отклоняется; переключение активной модели сериализовано.
- JSON читается ограниченным parser: превышение размера возвращает 413 с общим error envelope.

## Завершённые возможности

- История культур по непересекающимся датированным сезонам через `crop_seasons` в создании/изменении полигона. Анализ сохраняет собственный снимок истории и настроек источников.
- Квота сохранённых полей и сроки хранения опубликованы в capabilities.
- Сравнение до четырёх завершённых анализов возвращает общую ось и значения с исходными датами, происхождением и флагами качества. Выравнивание по сезону использует MM-DD, сохраняет 29 февраля и не сдвигает март невисокосного года.
- Экспорт CSV включает интервалы, severity, погоду и качество; числовые значения сохраняют точность. JSON/GeoJSON и отдельный доступный через API manifest содержат геометрию/версию, конфигурацию, модель, provenance и контрольные суммы.
- Retention удаляет истёкшие гостевые пространства, файлы экспорта и непривязанные старые снимки. Активный worker сначала подтверждает отмену; снимки с действующими ссылками сохраняются. Очистка не следует за путями за пределы `ARTIFACT_ROOT`, не затрагивает registry моделей. Истёкший экспорт продолжает отвечать 410.
- Структурированные HTTP-логи содержат request_id, код ответа и время обработки; cookie и параметры пользователя не включаются.

## Воспроизведение

```sh
.venv/bin/python backend/manage.py migrate
.venv/bin/pytest backend/tests -q
.venv/bin/python backend/manage.py cleanup_retention
```

Regression tests покрывают workspace isolation/CSRF, версии геометрии, конкурентную идемпотентность, отмену перед публикацией, lineage повторов, историю культур, геометрию и мировые bbox, экспорт/manifest, календарное выравнивание, сроки хранения и сохранение разделённых снимков. Тесты провайдеров используют записанные данные и заглушки; доказательства живого сбора хранятся отдельно.

Операторская `seed_demo` создаёт реальный датированный контур для CLI, без публичной браузерной demo-сессии. Общий read-only demo workspace и пользовательское копирование demo через frontend остаются отдельным продуктовым сценарием. Единичные замеры HTTP не заменяют нагрузочное испытание.
