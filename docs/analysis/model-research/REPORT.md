# Второй этап ML: проверка кандидатов и калибровка

Исследование выполнено локально на CPU 05.09.2026. Выбран **CatBoost residual без погоды** (`m5_without_weather`): RMSE **0,079287** на development points (4 482 контрольных предсказания). M0 на тех же folds — 0,090611. Это локальные результаты; официальный test RMSE неизвестен.

## Протокол и ограничения независимости

Исходный train: 99 955 строк, 39 AOI, 30 520 известных целей. Восемь полей из уже просмотренного старого holdout полностью исключены из обучения, выбора, калибровки и новой оценки. Остальные 31 AOI при seed=42 разделены до расчёта кандидатов: 21 selection, пять calibration, пять assessment. Точный состав и исходный SHA-256 — в [split_manifest.json](split_manifest.json).

Все эти 31 AOI уже встречались в прежнем исследовании baseline. Новая assessment отделена от нового выбора, но **не является новым слепым holdout**. После просмотра её результатов параметры не менялись. Данные 2024 года не входят в global fit; temporal assessment оценивает выбранную модель на 2024 году для selection+assessment AOI, исключая calibration AOI и старый holdout.

На selection выполнены пять GroupKFold по AOI, две фиксированные маски (42, 137), точки и календарные блоки 8/15/30/45/65 суток. Частота point mask — 15% известных целей; это модель пропусков, а не точная копия механизма test. Все сенсоры, погода, цель, предоставленная норма, status, z и неизвестные derived columns в контрольных строках скрываются до расчёта. Дата, статический crop и ключ остаются; календарь пересчитывается. Публичная климатология не использована ни в одном кандидате.

В каждом fold глобальные priors и CatBoost обучаются только на train AOI до 2024. Итоговый artifact обучен на 14 977 пригодных целях 21 selection AOI до 2024 и **не переобучен на calibration/assessment**. Это сохраняет соответствие модели её интервалам и оценке, хотя использует меньше обучающих данных. Веса и сезонные priors, training_scope, input/lock/source hashes, split/mask hashes и native JSON CatBoost хранятся в `ml/artifacts/final`.

В point scopes у всех кандидатов N=4 482, в blocks N=4 430. Метрики считаются по исходным скрытым целям без исправления y_true. Полные MAE, bias, p95, N, AOI bootstrap 95% interval, медиана и p90 ошибки по полям, срезы crop/year/gap/origin/AOI/sensor и fallback rate находятся в [report.json](report.json); краткая таблица — [metrics.csv](metrics.csv). Bootstrap пересэмплирует целые AOI (1 000 повторов, seed=42), сохраняя зависимость повторных масок.

- M0 — среднее двух соседей; M1 — линейная по календарному времени; M2 — PCHIP без собственной экстраполяции.
- M3 — Whittaker на ежедневной сетке, штраф второй разности λ=20, четыре Huber-итерации; `without_robust` — одна итерация. Пригодные реальные наблюдения всегда сохраняются: сглаживание применяется только к пропускам. Robust-вариант улучшает отдельные точки, но ухудшает длинные блоки.
- M4 — историческая медиана годовых окон ±15 дней по тому же AOI/crop, не менее трёх предыдущих сезонов, плюс локально интерполированный остаток. Без history он совпадает с M1. История помогает блокам (0,117322 против 0,129764), но ухудшает point objective. История текущего сезона в норму не попадает.
- M5 — 160 деревьев CatBoost глубины 4, learning_rate=0,04, l2=10, seed=42, CPU threads=2. Обучается residual к M0 на отдельной внутренней 20% маске train AOI. Признаки: M0, календарные sin/cos, gap/support/fallback и интерполированные соседние sensor/weather values. Статический AOI ID не используется. Соседние сенсоры/погода берутся только в пределах 14 дней и собственного сезона; NaN сохраняются. Маски скрывают все target-date covariates. Ограничение EVI |x|≤2 применяется только к clean features, raw EVI не переписывается; к NDVI/NDWI применяется |x|≤1.
- Исключение sensor features ухудшило point RMSE с 0,079416 до 0,086966. Погода не дала улучшения: без неё 0,079287. Поэтому final не требует погоды для восстановления; она остаётся полезна для фактического описания погодного контекста событий. Разница с вариантом с погодой мала и не доказывает универсальную бесполезность погоды.
- Raw/quality и clipping абляции на selection совпали: в этой части train нет out-of-range NDVI, а предсказания M0 уже ограничены диапазоном соседей. Это **не доказательство** ненужности фильтрации для других данных. Единственная out-of-range цель полного train не входила в selection.

Выбор зафиксирован по минимальному pooled development_points RMSE. Пороговые правила остаются исходными: gap≤60 дней, перенос края≤14 дней. M6 routing/ensemble не включён: на этом этапе оценивались одиночные кандидаты и обязательные абляции, новых весов после assessment не подбирали. DL (M7/P3) не запускался.

## Отложенная оценка и интервалы

Для выбранной модели assessment points: N=511, RMSE=0,082415; blocks: N=514, RMSE=0,128748. Temporal 2024 points: N=282, RMSE=0,066037; blocks: N=286, RMSE=0,140835. Высокая ошибка блоков — существенное ограничение; хороший результат единичных точек не означает надёжного заполнения длительных пропусков.

Калибровка — empirical absolute residual quantiles на пяти отдельных AOI, 1 173 контрольных точках (point+block mask seed=991). Уровень 90%, группы short≤30, long>30, edge, prior; если N<100 — pooled fallback. Радиус edge/long/prior не может быть уже short. Нет нормировки на историческую std. Параметры сохранены в модели и не корректировались по coverage assessment.

| Scope | N | Фактическое покрытие | Средняя ширина NDVI |
|---|---:|---:|---:|
| assessment_blocks | 514 | 87.74% | 0.3730 |
| assessment_points | 511 | 90.80% | 0.2473 |
| calibration_blocks | 622 | 90.19% | 0.3784 |
| calibration_points | 551 | 90.74% | 0.2483 |
| temporal_blocks | 286 | 85.31% | 0.3712 |
| temporal_points | 282 | 92.55% | 0.2442 |

На блоках имеется **недопокрытие** относительно номинальных 90%. Значения по calibration — проверка самой калибровки, не независимая оценка. Наблюдения внутри AOI и повторные маски зависимы, поэтому метод называется empirical residual, а не гарантированный split conformal. Для live устанавливаются method=`empirical_residual_domain_shift` и флаг `domain_shift`; подтверждённого live покрытия нет. Для observed даты prediction interval остаётся null: ошибка измерения спутника этим методом не оценивалась. Backend также может вернуть unavailable для live без наблюдений.

## Норма и события

Историческая норма отделена от reconstruction: для каждого разрешённого предыдущего сезона берётся медиана окна, центр — медиана сезонных значений, scale — 1,4826×MAD. При scale<0,01 zscore=null/degenerate_reference. Требуются три сезона; культура сравнивается явно. Метод mean/std доступен только явным параметром для сопоставления старого baseline. `robust_reference` отражает новую политику. Синтетически скрытые значения history исключаются.

Границы z сохранены: normal≥−1, stress [−2,−1), critical<−2. Fully reconstructed период не создаёт подтверждённого события. Длительный gap, слабая поддержка или domain shift снижают confidence. В события добавлена фактическая доля погоды; недостаток помечается weather_missing. Одиночный критический spike остаётся single_observation_alert. Причины являются проверяемыми гипотезами, а не диагнозом.

Независимых реальных labels засухи/болезни нет; precision/recall причин и экспертная агрономическая верификация не заявляются. Анонимные CSV не имеют координат и не доказывают перенос между регионами. Live-ряды и их качественный разбор сохраняются отдельно от benchmark-метрик.

## Воспроизведение и артефакт

```sh
uv sync --frozen
uv run --frozen python -m terralens_ml research --config ml/configs/research.yaml
uv run --frozen python -m terralens_ml predict --input test-dataset.csv --output artifacts/submission.csv --model ml/artifacts/final/manifest.json
uv run --frozen python -m terralens_ml validate-submission --input test-dataset.csv --submission artifacts/submission.csv
uv run --frozen pytest ml/tests -q
```

Pipeline сохраняет план до экспериментов и отклоняет другой план в том же output. Полные контрольные ключи каждой маски и predictions.csv находятся в локальном `artifacts/research`; они воспроизводятся командой и исключены из Git. Компактные hashes/метрики/split включены в репозиторий. CatBoost хранится в проверяемом native JSON внутри model.json; произвольные pickle не загружаются. Для инференса сеть, Django, Redis и БД не требуются.

Внешние датасеты и готовые внешние модели не использовались. Исходные CSV предоставлены в проекте; лицензия исходных данных не указана. Новых прав на их публичное распространение исследование не заявляет. Программные зависимости закреплены общим uv.lock.
