# Проверка TerraLens для жюри

## 1. Запуск и готовность

Из корня выполнить `docker compose up --build -d`, дождаться готового backend и открыть [приложение](http://localhost:3001/app). Авторизация через отдельный аккаунт не требуется: создаётся гостевая сессия.

Проверить [readiness](http://localhost:8000/api/v1/health/ready) и [Swagger](http://localhost:8000/api/v1/docs). Модель регистрируется автоматически. Если страница ещё недоступна, посмотреть `docker compose ps` и `docker compose logs --tail=80 migrate backend frontend`. При занятом порте frontend можно задать `FRONTEND_PORT=3002` в `.env` и добавить этот origin в `CSRF_TRUSTED_ORIGINS`.

## 2. Основной пользовательский маршрут

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| Контур | Найти Potsdam, приблизить карту, запросить контуры OSM | Кандидаты содержат источник; отсутствие кандидатов не запрещает рисование |
| Рисование | Добавить ≥3 вершины, замкнуть первую точку или нажать Enter | Видимый замкнутый контур и возможность сохранить поле |
| Импорт | Вставить геометрию из `backend/tests/fixtures/potsdam.geojson` через ввод GeoJSON | Поле сохраняется с площадью и версией |
| Паспорт | Переименовать поле и добавить историю культур | Название меняется без подмены версии геометрии; конфликты версий видны |
| Анализ | Выбрать 01–10.06.2024, источники Sentinel-2, Landsat и погоду | Фоновая задача, общий прогресс всех источников и предыдущих сезонов |
| Результат | Открыть динамику NDVI, выбрать дату | Наблюдения и восстановленные значения различимы; пропуск не становится нулём |
| Качество | Открыть качество и аномалии | Доступны покрытие, исключения, происхождение и ограничения; отсутствие нормы объяснено |
| Сравнение | Выбрать два завершённых анализа | Общая ось дат или сезонное MM-DD; выбор сохраняется в URL |
| Экспорт | Создать CSV, GeoJSON и JSON | Скачивание результата и manifest; checksum можно проверить локально |

Новый сбор может занимать несколько минут и зависит от внешних источников. `partial` не означает поломку: проверяйте предупреждения конкретного run. Исторические сезоны необходимы для нормы и увеличивают число запросов. Переименование поля не пересчитывает старый анализ, изменение контура создаёт новую версию.

## 3. Ошибки и пограничные случаи

| Проверка | Поведение |
|---|---|
| Невалидный или самопересекающийся полигон | Ошибка валидации, поле не создаётся |
| Конец периода раньше начала, невозможная дата | Запуск отклоняется с объяснением |
| Только погодный источник | Анализ растительности не запускается |
| Повторная отправка с тем же Idempotency-Key и телом | Возвращается тот же run/job, а не второй расчёт |
| Отмена в процессе сбора | Проверяется на checkpoint; неполный результат не публикуется как готовый |
| Отказ одного спутника | Второй источник может дать частичный результат с предупреждением |
| Нет пригодных наблюдений | `no_data`, отсутствие оценок и ясное объяснение |
| Недостаточно прошлых сезонов | Норма/z-score недоступны, не выдумываются |
| Обновление страницы или скрытие sidebar | Состояние приложения и размер карты остаются корректными |
| Другая гостевая сессия | Приватные поля, runs и экспорты первой сессии недоступны |
| Клавиатура, узкий экран, reduced motion | Доступная навигация, читаемые контролы, статические альтернативы WebGL |

Автоматические сценарии: `backend/tests`, `ml/tests`, `frontend/tests/e2e`. Они включают записанные ответы провайдеров и тестовые растры; такие тесты не являются новыми наблюдениями со спутника.

## 4. Проверка модели без приложения

После сборки Python-образа:

```sh
docker compose run --rm --no-deps batch predict --input test-dataset.csv --output artifacts/submission-check.csv --model ml/artifacts/final/manifest.json
docker compose run --rm --no-deps batch validate-submission --input test-dataset.csv --submission artifacts/submission-check.csv
```

Проверить 3 112 строк и SHA-256 `0fd8aebc5297d2e57d9244ca71e401660ac309d4cc2a1a0b2d595963530c02e1`. Эти команды проверяют воспроизводимость и формат. Отдельная локальная оценка по позднее предоставленным ответам дала RMSE **0,075034**, GapScore **7,49 / 30**; результат платформы не получен. Для второго входа `test_features.csv` подготовлено 2 323 прогноза без оценки RMSE: приложенные ответы относятся к первому входу. [Соответствие файлов и команды оценки](CASE_AUDIT.md), [готовые файлы](../deliverables/README.md).

Для проверки автономности в отдельном Python 3.12 окружении из корня:

```sh
uv venv .venv-release
uv pip install --python .venv-release/bin/python -c requirements.lock ./ml
.venv-release/bin/python scripts/verify_offline.py --require-standalone
```

На Windows заменить `.venv-release/bin/python` на `.venv-release/Scripts/python.exe`. Скрипт блокирует сеть на время проверки, выполняет повторный инференс и сверяет результат. В standalone окружение не устанавливаются Django/Celery/Redis.

Полное переобучение — `uv run --frozen python -m terralens_ml research --config ml/configs/crop-dynamics.yaml`; оно затратнее инференса, использует зафиксированные splits/seeds и сохраняет результаты в `artifacts/crop-dynamics`. Для воспроизведения выбора без final fit добавить `--development-only`. [Научный протокол](analysis/crop-dynamics/PROTOCOL.md).

## 5. Сквозная проверка живого API

При запущенном Compose и Python workspace:

```sh
uv sync --frozen
uv run --frozen python scripts/api_smoke.py --reference-years 3 --output artifacts/jury-smoke
```

Скрипт создаёт отдельную сессию и поле, запускает реальный анализ, дожидается Celery, читает все страницы ряда, проверяет три формата экспорта и manifests. Затем выполняет 40 чтений при concurrency=4. `artifacts/jury-smoke` содержит запрос, job/run, ряд, экспорты и замеры без cookies. Значение p95 из этого smoke относится только к небольшому локальному стенду и не является нагрузочным SLA.

Для более короткой проверки убрать `--reference-years 3`: по умолчанию исторические сезоны отключены. Для второго региона добавить `--geometry backend/tests/fixtures/seville.geojson`.
