# Соответствие TerraLens материалам кейса

Дата сверки: **5 сентября 2026**. Проверены семь предоставленных файлов, опубликованный код, артефакты модели и отчёты. Исходная версия для сверки: `9ea5be2a71645a728ceec6e9489711a453fc9a4b`. Контрольные суммы и размеры — в [materials.json](analysis/input-review/materials.json).

TerraLens решает задачу мониторинга вегетационной динамики сельскохозяйственных территорий: восстановление пропусков NDVI и поиск негативных периодов с контекстом. Название TerraLens — название нашего продукта. Источники требований: [постановка задачи](../постановка_задачи.pdf), 19 страниц, и [критерии приёмки](../критекрии_приёмки.pdf), 5 страниц. Исходные имена PDF в репозитории сохранены.

**Основной программный результат реализован, но максимальное выполнение всех критериев не подтверждено.** Есть веб-приложение, реальный сбор данных, самостоятельный ML-пакет, исследовательские отчёты и воспроизводимый запуск. Не найдена финальная презентация; существующие живые примеры не демонстрируют подтверждённую негативную аномалию. Новая локальная оценка готовой модели существенно ниже максимальных 30 баллов за метрику. Оценки экспертных критериев выставляет жюри.

Служебные записи `__MACOSX` в ZIP не являются данными кейса. В постановке тестовый вход назван `private_features.csv`; фактические вложения имеют другие имена и разный состав. CLI принимает путь к CSV или ZIP, имя файла не зашито в алгоритме.

У двух тестовых входов нет общих ключей `(anon_polygon_id, date)`. У нового набора нет пересечения ключей или AOI с train. Ответы из `private_test_ground_truth.csv` **точно совпадают с 3 112 контрольными ключами `test-dataset.csv`** и не совпадают ни с одним из 2 323 контролей `test_features.csv`. Одинаковая предметная область не делает эти наборы взаимозаменяемыми.

Указания о том, какой из двух наборов считать финальным для сдачи, не получены. Поэтому подготовлены два отдельных результата; основной опубликованный submission сохранён. Разметка из нового архива не включена в публичный репозиторий и не использована для обучения, калибровки или выбора модели.

## 2. Новая локальная оценка

До чтения ответов зафиксированы модель `131aee618934151e`, её manifest и ранее опубликованный submission. Во время сверки они не менялись. Их SHA-256 сохранены в [materials.json](analysis/input-review/materials.json); хеш исходного submission — `0fd8aebc5297d2e57d9244ca71e401660ac309d4cc2a1a0b2d595963530c02e1`.

| Показатель | Результат на приложенных ответах |
|---|---:|
| Контрольных точек / AOI | 3 112 / 78 |
| Совпадение множеств контрольных ключей | Полное |
| RMSE | **0,0750342359** |
| MAE | **0,0494095368** |
| GapScore по формуле кейса | **7,49 / 30** |

Формула: `round(30 * max(0, 1 - RMSE / 0.10), 2)`. Это **локальная оценка по предоставленному файлу ответов**, не результат платформы организаторов и не суммарная оценка проекта. Истинные значения не обрезались и не исправлялись. Метрики development, assessment и temporal в исследовательских отчётах относятся к другим выборкам; их нельзя подставлять вместо этого результата.

[Машиночитаемая оценка](analysis/input-review/local-score.json) воспроизводится из корня, Python 3.12, без дополнительных библиотек:

```sh
python scripts/score_submission.py --input test-dataset.csv --submission deliverables/submission.csv --ground-truth /path/to/doc-1788600416.zip --output artifacts/local-score.json
```

Замените `/path/to/doc-1788600416.zip` путём к полученному архиву. Поддерживается также сам `private_test_ground_truth.csv`. Скрипт требует полного совпадения ключей и отклоняет дубли, отсутствующие точки и бесконечные значения. После ознакомления с этими ответами дальнейшую настройку по ним нельзя выдавать за независимую слепую проверку.

## 3. Отдельный результат для test_features.csv

Файл [submission-test-features.csv](../deliverables/submission-test-features.csv) содержит **2 323** прогноза. [Manifest](../deliverables/submission-test-features.csv.manifest.json) фиксирует ту же модель, входной ZIP и SHA-256 результата: `1fabb4ed5df3b8ed404e218de0e69b5ebeb38240ce0ea65c88a3bade4dfdc497`.

Валидация формата, уникальности, конечности прогнозов и полного множества контрольных ключей прошла. В этом входе нет двух готовых колонок климатологии из первого test; существующий runtime обработал его без изменений кода и без переобучения. Подходящих правильных ответов для этих 2 323 точек в предоставленных файлах нет, поэтому RMSE для них не заявлен.

После сборки Docker, из корня проекта:

```sh
docker compose run --rm --no-deps -v "/path/to/doc-1788600393.zip:/inputs/test_features.zip:ro" batch predict --input /inputs/test_features.zip --output artifacts/submission-test-features.csv --model ml/artifacts/final/manifest.json
docker compose run --rm --no-deps -v "/path/to/doc-1788600393.zip:/inputs/test_features.zip:ro" batch validate-submission --input /inputs/test_features.zip --submission artifacts/submission-test-features.csv
```

Укажите абсолютный путь к архиву; на Windows подойдёт `C:/Users/USER/Downloads/doc-1788600393.zip`. Сам новый входной архив не входит в Git. Выходы двух наборов нельзя склеивать в один submission.

## 5. Что именно взято из данных и рекомендаций

- Train использован целиком при аудите; обучение, калибровка и проверки разделены по AOI и времени. Финальный fit использует 21 selection AOI до 2024 года: 79 256 маскированных примеров покрывают 14 977 пригодных целей. Неиспользование оценочных AOI для fit — часть протокола, а не потерянные данные.
- В выбранной модели 78 признаков локального ряда, календаря и сенсоров, включая доступные MODIS-колонки CSV. Погода исследовалась, но не включена в итоговый набор признаков; в приложении она используется для контекста. Категория культуры не входит в выбранную CatBoost-модель, но границы культур учитываются при подготовке рядов.
- Готовые `status`, `zscore` и климатология из CSV не подаются как признаки восстановления. Динамические значения скрытых контрольных строк удаляются перед построением признаков. Это защищает оценку от утечки.
- Для новых полей работают прямые открытые источники Sentinel-2/Landsat и погоды, OSM/Nominatim/Overpass. Живого MODIS-провайдера, GEE, WorldCereal и WorldCover в приложении нет. Постановка предлагает варианты источников; одновременное подключение всех перечисленных сервисов не требуется.
- Дополнительные спутниковые наблюдения собираются для анализа выбранного контура и предыдущих сезонов. Глобальное обучение на дополнительно собранном геопривязанном корпусе не выполнено. Внешние обучающие датасеты и готовые сторонние веса для финальной модели не заявляются.
- Проверены три реальных контура по заранее зафиксированному протоколу: Потсдам, Севилья и Воронежская область. Опубликованы ряды, негативный период, два случая недостатка нормы, сравнение M0 и модели, а также повторный расчёт без сети. Это измеренная проверка на конкретных полях, а не доказательство точности диагностики стресса по всему миру.

## 6. Комплект защиты и внешние условия

Презентация, сценарий защиты, ответы, три показательных ряда, графики, исходные таблицы и русские поясняющие комментарии подготовлены. В процессе проверки исправлен ошибочно уверенный сводный статус при недостаточном покрытии исторической нормы; [правило и регрессионные тесты](analysis/field-cases/REPORT.md) описаны вместе с результатами.

Остаются организационные действия: команде отрепетировать выступление и уточнить у организаторов финальный тестовый вход. [Готовый текст уточнения](DEFENSE_GUIDE.md) приложен; сообщение не отправлялось. До ответа сохранены два раздельных submission. Наличие материалов не означает присвоения 100 баллов.

Для повышения качества модели нужен отдельный экспериментальный план с новой независимой оценкой. Предоставленные ответы уже просмотрены; новые полевые примеры также стали известной диагностикой. Переобучение на них нельзя выдавать за улучшение на слепой проверке.
