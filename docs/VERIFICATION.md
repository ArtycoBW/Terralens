## Исправление прогресса анализа

Раньше каждый запрос спутника или прошлого сезона публиковал локальный процент и начинал шкалу заново. По БД проверенные jobs выполнялись с `attempt=1`: повторялась индикация, не весь запуск.

Теперь план включает все спутники и исторические сезоны. Кеш, пустые ответы, отказ источника и переходы между этапами не обнуляют прогресс. 100% появляется только после сохранения результата. Исторические данные имеют отдельное название этапа. Chart загружается во время расчёта; при публикации остаётся один этап подготовки результата. Повторное получение terminal state не вызывает повторный `onFinish` и invalidation при каждом рендере.

Семь новых Python-сценариев проверяют обе спутниковые системы, обычные/пустые/частично ошибочные ответы, кеш, границы доступной истории, 29 февраля и отмену. Новый браузерный сценарий задерживает ответ ряда и проверяет единственный переход от прогресса к готовому экрану без повторного запроса series; выполняется на desktop и mobile.

## Живой сквозной запуск

Выполнено:

```sh
uv run --frozen python scripts/api_smoke.py --reference-years 3 --output artifacts/jury-smoke
```

- Реальный контур Потсдама, период 01–10.06.2024, Sentinel-2 + Landsat + погода + три прошлых сезона.
- Job завершён с первой попытки. Получен `partial` с двумя днями пригодных наблюдений; ограничения сохранены в run.
- Все 39 зафиксированных состояний анализа подтверждают монотонный прогресс, финальное значение — 1.
- CSV, GeoJSON и JSON выгружены, manifests получены, SHA-256 проверены.
- 40 чтений при concurrency=4: p95 ≈41,64 мс, max ≈48,32 мс на небольшом прогретом локальном стенде. POST анализа ≈327,60 мс. Это проверка работоспособности, не SLA и не тест предельной нагрузки.

Повторная генерация submission в batch-контейнере дала 3 112 строк и SHA-256 `0fd8aebc5297d2e57d9244ca71e401660ac309d4cc2a1a0b2d595963530c02e1`, совпадающий с поставкой.

## Запуск из чистого клона

После подготовки публичного репозитория выполнена новая сборка из чистого Git checkout. Отдельный Compose-проект использовал новые volumes PostGIS и artifacts и отдельные локальные порты, без данных рабочего стенда.

Миграции и регистрация модели завершились автоматически. Frontend, readiness, создание гостевой сессии и чтение registry вернули HTTP 200. Проверены наличие session cookie/CSRF и активная модель `131aee618934151e`. Команды запуска из README не зависят от локальных рабочих материалов. Состав кода, датасеты и модель совпали с версией, прошедшей полный набор тестов и живой smoke.

## Что эта проверка не утверждает

Официальной скрытой разметки test нет. Все RMSE и интервалы относятся к указанным экспериментальным выборкам; независимая accuracy на произвольных реальных полях и нагрузочная пригодность не измерены. Внешние провайдеры могут менять доступность данных. [Протокол модели](analysis/crop-dynamics/REPORT.md) и [маршрут ручной проверки](JURY_GUIDE.md) содержат условия воспроизведения.
